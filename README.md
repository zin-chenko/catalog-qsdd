# catalog-qsdd

Angular-приложение Q.EDMS по макетам `Q.EDMS_макеты_с_комментариями.pdf`. Интерфейс на русском языке. Все данные, решения по документам, уведомления и ответы ассистента работают локально; сервер и внешние AI-сервисы не нужны.

## Запуск

Требуется Node.js 20.19+, 22.12+ или 24.x, совместимый с Angular 21.

```sh
npm ci
npm start
```

Открыть http://localhost:4200. Стартовый экран — папка «Приказы».

```sh
npm run build          # production-сборка в dist/catalog-qsdd/browser
npm test               # сценарии Playwright
npm run test:repository # проверка хранения и создания папок без браузера
npm run format:check   # проверка форматирования
```

В Windows тесты используют установленный Google Chrome. На других системах предварительно выполнить `npx playwright install chromium`. Браузер можно переопределить переменной `PLAYWRIGHT_CHANNEL`. Тесты самостоятельно запускают Angular dev server и используют отдельное хранилище для каждого сценария.

## Запуск в Docker

Требуется работающий Docker с Linux-контейнерами и Docker Compose. Node.js на хосте устанавливать не нужно.

```sh
docker compose up --build -d
```

Открыть http://localhost:8080. Dockerfile собирает production-версию Angular в Node.js 22, затем копирует только готовые файлы в nginx. Прямые ссылки на вкладки и обновление страницы поддерживаются. Проверка состояния: `http://localhost:8080/healthz`.

```sh
docker compose ps
docker compose logs -f
docker compose down
```

Для другого порта задать переменную `PORT` перед запуском, например в PowerShell:

```powershell
$env:PORT = '8081'
docker compose up --build -d
```

Порт по умолчанию доступен только локально. Для доступа из сети изменить привязку `127.0.0.1` в `compose.yaml` на нужный адрес. Моковые данные по-прежнему сохраняются в браузере, поэтому Docker volume не требуется. Хранилища для адресов `localhost:4200` и `localhost:8080` независимы.

## Что реализовано

- Шапка с глобальным поиском по атрибутам и тексту, уведомлениями, профилем и выбором замещающего сотрудника.
- Каталог папок, поиск внутри папки, фильтры по статусу, году, виду, автору, подразделению, тегу и периоду. Фильтры сохраняются в URL.
- Список документов: 128 приказов, сортировка всех столбцов, пагинация с реальным набором данных, выделение строки, открытие карточки.
- Карточка с атрибутами, связанным документом и файлами. Создание черновиков, редактирование автором или администратором, автоматические версии при сохранении.
- Предпросмотр основного документа, приложения, PDF и сканов; переключение файлов, масштаб, скачивание. Загруженные DOCX отображаются как извлечённый текст, без исполнения разметки документа.
- Маршрут согласования с участниками, комментариями, датами и текущим этапом. Администратор и инициатор могут добавлять участников и дополнительные этапы. Дополнительные этапы исполняются до подписания.
- Согласование, отклонение с обязательной причиной, делегирование и отправка черновика на согласование. Действия меняют документ и сохраняются после перезагрузки.
- Версии: просмотр предыдущего текста и сравнение любых двух версий с подсветкой изменённых абзацев. Зарегистрированные документы доступны только для чтения.
- Контекстная AI-панель с демонстрационными ответами, быстрыми запросами, переходами в документ и подсветкой пунктов. Из ответа можно создать поручение.
- Поручения: поиск, статусы, завершение и возврат в работу. Отчёты по текущим данным и выгрузка CSV. Эти два дополнительных раздела оформлены в стиле макетов: отдельных экранов для них в PDF нет.
- Адаптация под узкие экраны: выдвижной каталог и переключаемая панель ассистента.

## Настройка каталога

Кнопка «+» рядом с заголовком «КАТАЛОГ» создаёт папку в корне. Кнопка «+» справа от обычной папки создаёт подпапку; расположение можно изменить в диалоге. Поддерживаются несколько уровней вложенности, создание документов внутри новых папок и открытие по прямым ссылкам. Название — до 100 символов; одинаковые названия на одном уровне не допускаются. «Центр документов» и «Контроль поручений» — служебные разделы, в них нельзя создавать подпапки.

Каталог сохраняется вместе с документами в браузере. Сохранённые данные прежней версии автоматически получают начальную структуру папок без сброса документов. Изменения каталога не синхронизируются между браузерами или сотрудниками.

## Маршруты

Верхняя вкладка «Маршруты» открывает список пользовательских маршрутов. Кнопка «Создать маршрут» открывает редактор: укажите название и добавьте последовательные шаги. У каждого шага есть название, исполнитель (подсказки из справочника или собственное имя) и тип: «Согласование» или «Подписание». Стрелки меняют порядок, крестик удаляет шаг. Для сохранения нужен хотя бы один полностью заполненный шаг.

«Редактировать» меняет существующий маршрут. «Дублировать» сразу сохраняет независимую копию с уникальным названием и открывает её для редактирования. Отмена закрывает редактор без сохранения введённых изменений; уже созданная копия остаётся в списке. Поиск работает по названиям маршрутов, шагов, исполнителям и типам шагов.

Маршруты сохраняются в том же локальном хранилище браузера, что и документы. В карточке документа кнопка «Запустить согласование» открывает выбор маршрута с предпросмотром шагов и исполнителей. Кнопка запуска — UI-заглушка: показывает сообщение о демонстрации, не меняет документ и не запускает процесс. Диалог можно открывать повторно для любого документа. При отсутствии маршрутов есть переход к их созданию. Фактический запуск будет подключён к BPM позднее.

## Данные и роли

Начальный пользователь — Смирнова Е.А., согласующий HR-департамента. В профиле можно переключиться на роль администратора, чтобы проверить редактирование чужого документа и изменение маршрута.

Исходные данные находятся в `src/app/core/mock-data.ts`. Первые семь приказов и история приказа № 214-П воспроизводят макет; остальные записи сгенерированы для проверки каталогов и пагинации. Счётчики рассчитываются по локальным данным. На «Центре документов» счётчик отражает документы, ожидающие решения пользователя; в остальных папках — число записей, у поручений — незавершённые задачи.

Изменения хранятся в `localStorage` под ключом `catalog-qsdd.demo.v1`. Для возврата к исходным данным удалить только этот ключ в инструментах разработчика и обновить страницу:

```js
localStorage.removeItem('catalog-qsdd.demo.v1');
location.reload();
```

## Подключение бэкенда

Компоненты работают через `EdmsStore` и абстрактный `EdmsRepository`. Его текущая реализация — `MockEdmsRepository`. Все операции чтения и изменения имеют асинхронную сигнатуру, обработку ошибок и состояние выполнения. Для подключения API нужно реализовать HTTP-репозиторий и заменить provider в `src/main.ts`.

Предложенные эндпоинты, параметры и ответственность сервера описаны в [docs/backend-contract.md](docs/backend-contract.md). Это проект будущего контракта, а не существующий API. Сетевых запросов к нему сейчас нет.

## Границы демоверсии

- AI-ответы формируются по локальным правилам. Реального LLM, векторного поиска и полнотекстового индекса нет.
- Авторизация, ограничения доступа, электронная подпись, регистрация, отправка уведомлений и фактическая передача полномочий замещающему сотруднику требуют сервера. Локальная роль предназначена для проверки интерфейса.
- Предпросмотр макетных DOCX основан на HTML-тексте; для произвольных загруженных DOCX сохраняется текст, но не сложная исходная вёрстка. Для точного Word-рендеринга нужен сервис конвертации в PDF.
- Лист согласования — встроенный демонстрационный PDF по исходному приказу № 214-П. Его автоматическая регенерация при изменении маршрута предусмотрена будущим API. Данные основного DOCX при скачивании соответствуют выбранной редакции.
- История хранит заголовок и текст редакций; отдельное бинарное содержимое каждого файла по каждой версии должен хранить сервер.
- Загрузка ограничена 2 МБ на файл из-за хранения в браузере. Поддерживаются DOCX, PDF, PNG, JPEG, WebP. При исчерпании квоты показывается ошибка, частичная операция откатывается.
- Вкладки открываются по прямым адресам. При размещении production-сборки веб-сервер должен возвращать `index.html` для клиентских маршрутов.

## Структура

```text
src/app/core/                 модели, исходные данные, репозиторий, store, файлы
src/app/features/documents/  пять вкладок, формы и предпросмотр
src/app/features/assistant/  контекстный помощник
src/app/features/tasks/      поручения
src/app/features/reports/    сводные отчёты
src/app/shared/              иконки, статусы, доступный диалог
public/mock/                демонстрационный PDF
tests/                      пользовательские сценарии Playwright
```

Шрифт Inter поставляется внутри приложения. Для работы интерфейса не требуются CDN, Google Fonts или подключение к интернету.
