# Минимальное подключение QPalette

Статус: QPalette 8.1.3 установлена из корпоративного Nexus, версии сохранены в package.json и pnpm-lock.yaml. Production-сборка платформенного входа проходит. Вход/выход пользователя и запуск внутри настоящего rootapp **ещё не проверены**: нужен стенд авторизации. Успешная компиляция не означает готовность защищённой публикации.

## Два режима

- `pnpm start` / `pnpm run build` — существующее автономное демо. Не включает QPalette в браузерный бандл и не содержит авторизации. При чистой установке зависимостей репозитория Nexus теперь нужен, поскольку пакеты QPalette входят в общий manifest/lockfile.
- `pnpm run start:qpalette` / `pnpm run build:qpalette` — отдельный entry point с `createApplication`, `provideQCore`, `provideQAuth`, Angular HTTP DI-перехватчиками и `QWebComponent`. Предназначен для загрузки авторизованной оболочкой QPalette. Команда dev server только отдаёт бандл на порту 4201, она не запускает rootapp и сервер входа.

Вход, обновление сессии и выход должны обслуживаться оболочкой QPalette, как в qedmsui. Собственная форма пароля, второй Keycloak-клиент, хранение токенов и таймер обновления сессии в каталог не добавлены. Ошибка запуска платформенного входа не переключает его в демо.

## Установка и сборка

```sh
pnpm install --frozen-lockfile
pnpm run build:qpalette
```

Запускать именно в этом порядке: сначала дождаться успешного завершения установки, затем собирать. Перед сборкой и dev-запуском проверяются наличие и версии пакетов; при их отсутствии Angular не запускается и выводится инструкция по установке.

Команда `pnpm run setup:qpalette` оставлена для явной синхронизации версий из `config/qpalette-packages.json`; она обновляет manifest и lockfile. Скрипт поддерживает JavaScript-версию pnpm и standalone `pnpm.exe`. Для обычной установки уже зафиксированных зависимостей достаточно frozen lockfile. npmjs не заменяет корпоративный Nexus для QPalette.

В `.npmrc` публичные зависимости (например, `webpack`) направлены в npmjs, а `@diasoft/*` — в Nexus. Если ошибка загрузки касается `@diasoft/qpalette-*`, нужно проверить доступ к корпоративному репозиторию. Фраза `No authorization header was set` сама по себе не доказывает, что причиной был отсутствующий токен; токены не следует добавлять в репозиторий.

Далее:

1. На тестовом rootapp подключить каталог как продуктовый бандл. Папка сборки — `dist/catalog-qsdd-qpalette`, имя основного файла — `main.js`. URL и регистрация сервиса зависят от схемы gateway конкретного стенда; выбрать их с владельцем стенда.
2. Использовать существующую конфигурацию авторизации rootapp. `config/qpalette-host.example.json` — только пример фрагмента из qedmsui для сервиса `default`, не готовая конфигурация Keycloak и не файл, который читает каталог. Объединять настройки на стороне оболочки, сохраняя её адреса и параметры входа.
3. Типы импортов проверены production-компиляцией. На стенде проверить обязательные DI-провайдеры и запуск внутри rootapp. Если используемая оболочка требует Transloco/PrimeNG-провайдеры внутри продукта, добавить их по API установленной версии.
4. Проверить вход с истёкшей/отсутствующей сессией, обновление страницы с прямым URL, обновление токена, выход и повторный вход. Неавторизованный пользователь не должен получать интерфейс через оболочку. Отдельно проверить, что токены не попадают в журналы и не отправляются за пределы API стенда.

Основной Dockerfile продолжает собирать автономное демо. Для корпоративной сборки добавлены отдельный `docker/Dockerfile-pbcui.txt`, минимальный `rootapp` и Jenkinsfile по шаблону qedmsui — см. [jenkins.md](jenkins.md). Сервер авторизации задаётся инфраструктурой стенда; отдача демо-контейнера через nginx авторизацию не включает.

## Производительность

Платформенные импорты находятся только в `src/qpalette/`; обычная сборка их не включает. Каталог не подключает загрузчик виджетов, библиотеки бизнес-компонентов, темы QPalette или глобальные стили PrimeNG. `qpalette-urls`, PrimeNG, CDK и Transloco нужны как зависимости платформенных пакетов. Нельзя гарантировать, что сборщик удалит весь неиспользуемый код без измерения настоящих пакетов.

Сохранены ленивые разделы, производственная оптимизация и прежний бюджет начальной загрузки: предупреждение 700 kB, ошибка 1 MB. Бюджет не увеличен для сокрытия роста. После установки нужно сравнить production stats, передаваемый с компрессией объём и время открытия каталога на одном стенде; при превышении сначала разобрать состав бандла. Не добавлены опросы сервера, дублирующие слушатели сессии или принудительные циклы `ApplicationRef.tick()`.

Измерение QPalette production-сборки: начальная загрузка **975.36 kB**, оценка передачи **232.90 kB**. Удалён явный импорт `@angular/compiler`: шаблоны компилируются при сборке (AOT). До удаления импорт увеличивал начальную загрузку до 1.46 MB. Лимит ошибки 1 MB сохранён, предупреждение 700 kB остаётся. Это измерение размера, а не времени работы на стенде.

Для сравнения, ранее измеренная автономная production-сборка: 623.38 kB, оценка передачи 153.69 kB. После установки QPalette прошли все 15 браузерных сценариев деморежима; `pnpm peers check` не обнаружил конфликтов.

## Данные и права

Данные каталога пока остаются моковыми, профиль и переключатель роли внутри демо не являются правами QPalette. Подключение `provideQAuth` само по себе не превращает локальные данные в защищённый API и не реализует разграничение прав. При появлении бэкенда сервер должен проверять токен и полномочия каждой операции, а профиль каталога нужно связать с подтверждённым API пользователя QPalette. До проверки на стенде эту заготовку нельзя считать завершённой авторизацией.
