# Jenkins по шаблону qedmsui

`Jenkinsfile` вызывает ту же shared library `dsMsaPipeline` с `metadata_type=pbcui` и `build_tool=npm`. Значение `npm` — имя сборочного инструмента в шаблоне; внутри Docker используется pnpm, как в qedmsui. Job каталога независима от job qedmsui и не читает соседний репозиторий.

## Настройки

| Параметр                    | Значение                                                   |
| --------------------------- | ---------------------------------------------------------- |
| Бандл                       | `QSDDUI`                                                   |
| Сервис и компонент QPalette | `qsddui`                                                   |
| Dev                         | `qrun.dev-qedms`                                           |
| Автотест                    | `qrun.autotest-qedms`                                      |
| Prod                        | `qrun.prod-qedms`                                          |
| Ветки production            | `main` и `master`                                          |
| Остальные ветки             | dev                                                        |
| Node.js                     | 22                                                         |
| Runtime                     | корпоративный `release/qpalette`, порт 8080, UID/GID 10001 |

Окружения подтверждены пользователем. Системное имя нового бандла выбрано отдельно от QEDMSUI; при регистрации сервиса в платформе нужно использовать именно `qsddui`. Production включён для `main`, поскольку это основная ветка каталога, и для `master`, как у образца. Адрес уведомлений команды qedmsui не копировался.

## Подготовка исходников

Шаблон ожидает папку `Q*UI`, `rootapp` и ignore-файлы в контексте сборки. `pbcui_build_command_bundle` вызывает `scripts/prepare-jenkins.mjs ..` из checkout, используя те же подстановки `[BASE_DIRECTORY][PBC_DIRECTORY]`, что и qedmsui.

Скрипт копирует только необходимые исходники в `QSDDUI`, добавляет `rootapp`, корпоративный Dockerfile и ignore-файлы. В копии `prod` запускает **QPalette-сборку**, выдавая `dist/qsddui/main.js`. Локальный `package.json` не меняется, lock-файл копируется без изменения. Повторная подготовка требует чистой папки `QSDDUI`, чтобы не включить старые файлы. Контекст Docker ограничен подготовленными каталогами; checkout, node_modules и локальные настройки в образ не копируются.

Ручная подготовка из корня репозитория:

```sh
node scripts/prepare-jenkins.mjs tmp/jenkins
docker build -f tmp/jenkins/docker/Dockerfile-pbcui.txt tmp/jenkins
```

`docker/Dockerfile-pbcui.txt` использует образы и digest из qedmsui. Он рассчитан на подготовленный контекст, а не на корень checkout. Основной `Dockerfile` и `docker compose` продолжают собирать локальное демо.

## Источники зависимостей и условия первого запуска

В CI все зависимости направляются через корпоративный Nexus, как у qedmsui. Локальная маршрутизация npmjs / `@diasoft` не переносится в сборочный контекст. Значит, Nexus должен отдавать также публичные пакеты, например `webpack`. Зависимость извлечения текста DOCX, которая возвращала 404, удалена вместе с её транзитивными пакетами; полный CI install оставшихся пакетов ещё нужно проверить.

QPalette 8.1.3 установлена, зависимости сохранены в **package.json и pnpm-lock.yaml**. CI использует frozen lockfile и не выполняет установку новых зависимостей командой `setup:qpalette`. Локальная QPalette production-сборка проходит. Если зависимости QPalette отсутствуют, сборка завершается ошибкой; демоверсия вместо неё не публикуется.

В Jenkins нужна та же доступная shared library `dsMsaPipeline`, доступ к Nexus/registry и регистрация отдельного сервиса в платформе. Секреты и адреса сервера входа задаются инфраструктурой стенда. `rootapp` содержит минимальную конфигурацию и меню каталога; режим `auth.service=default` взят из qedmsui. Это не подтверждает работоспособность авторизации без тестирования на стенде.

## Проверка

Локально проверяется подготовка контекста, согласованность имён бандла/меню/выходной папки, сохранность исходного manifest и lockfile, отсутствие node_modules и `.git` в бандле. Jenkins shared library и корпоративные образы локально недоступны; запуск job, Docker-сборка в корпоративной сети и авторизация QPalette требуют проверки в инфраструктуре. Kubernetes-манифесты не добавлены: развертыванием управляет существующий шаблон.
